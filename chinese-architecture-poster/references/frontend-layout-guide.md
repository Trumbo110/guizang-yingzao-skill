# 真实字体排版垫图工作流

当海报依赖严格的共享边线、结构性大字、竖排、跨栏或文字—建筑遮挡时，先用前端制作排版垫图，再让图像模型整体重绘。这个方法提高构图服从度，但不承诺像素级字形复制。

## 为什么有效

纯文字提示词只能描述“六栏”“左对齐”“标题被屋檐遮挡”等抽象关系；图像模型仍需要自行估算每个边界框。垫图把这些关系直接变成像素证据：

- 字体的宽窄、字面大小、字距和行距已经可见；
- 元素从哪一栏开始、跨几栏、与哪条边共享对齐已经可见；
- 文字和建筑在哪个位置接触、谁在前、谁被裁切已经可见；
- 大字、标签、规则线和负空间的面积关系已经可见。

模型仍会重新绘制字形，所以可能出现几个像素的漂移、字宽变化或局部笔画差异。该流程的目标是“版式明显守规矩且材质统一”，不是印刷制版级还原。

## 选择垫图模式

### `layout-only`：默认

垫图不包含任何原照片像素。使用中性灰色多边形、矩形或简单剪影标出建筑占位、主导轴、屋檐方向和遮挡边界。它是默认方案，尤其适用于限色、版画、网点、线刻、拼贴或完全替换天空。

这样能把“布局控制”和“图像处理”解耦：Image 2 不能诱导模型保守复制原照片，建筑材质只能由 Image 1 和提示词重新推断。

### `photo-overlay`：摄影保留模式

把原照片作为垫图底层，只在其上排字。仅在用户明确要求轻度调色、摄影封面或最大限度保持自然天空与材料细节时使用。它能更准确地预演文字—建筑接触位置，但容易让模型把垫图当成半成品，从而降低风格化幅度。

不要在需要明显艺术转译时使用 `photo-overlay`。

## 字体来源

优先级：

1. 明确授权且本机已安装的字体；
2. 下载到项目或缓存中的开源字体文件，通过 `@font-face` 引用；
3. Google Fonts 等远程字体，只在网络稳定并等待 `document.fonts.ready` 后使用；
4. 系统字体栈作为后备。

不要依赖浏览器悄悄回退字体。截图前检查实际字体名称和中文覆盖；远程字体加载失败时停止渲染或切换到已知本地字体。

## 制作垫图

1. 先解析本次 Recipe/Token，记录完整 Token ID 清单；不要直接把 Recipe 名当作 CSS 类或提示词。
2. 先对照片做主体预检：标出建筑中轴、可用水平参照、相机滚转、梯形透视、真实屋坡和真实不对称。需要校正时先生成扶正后的建筑底图并重新裁切；垫图中的中性主体占位以校正后范围为准。
3. 画布匹配最终比例和预期输出尺寸。
4. 根据 `cap.primitive.grid-*`、`cap.primitive.margin-standard`、`cap.primitive.gutter-standard` 和 `cap.primitive.optical-alignment` 建立 CSS Grid、外边距、沟槽、基线与字面对齐变量。
5. 默认使用 `layout-only`：以中性占位形状标出建筑范围和主导轴，不嵌入原图；只有用户明确要求摄影保留时才把原图作为底层。
6. 使用最终真实文案和字体，按 `cap.type.*` 设置展示标题、结构性大字、地点标签和资料文字。
7. 用 `clip-path`、蒙版或明确的 z-index 执行 `cap.layout.*` 与 `cap.depth.*`；不要为了精细抠图而牺牲排版决策速度。
8. 在元素上记录 `data-token="cap..."`，在根节点记录本次解析后的 Token 清单，便于检查和回溯；同一元素可以消费多个不同类别 Token。
9. 导出：
   - `grid-check.png`：显示栏线和基线，仅用于人工检查；
   - `layout-guide.png`：关闭栏线和调试框，保留最终近似版式，作为模型输入。主题文字模式不保留任何功能线；解释注释模式只保留蓝图列出的线。

最少检查：建筑扶正轴、裁切边界、共同左边线、共同右边线、中轴、基线组、文字块宽高、可见字面边界、换行、竖排方向、强调色连接对象和身份保护区。解释注释模式再检查规则线端点。

`visual.swatch` 只用于 Token 目录预览，不能直接复制到垫图。垫图中的具体色值由 `cap.color.material-derived` 和目标照片取色覆盖。

## 把网格变成约束，而不是背景装饰

每个主要元素必须记录四个值：`column-start`、`column-span`、`baseline-start`、`baseline-span`，并加入一个 `alignment-group`，说明它与哪些元素共享左边、右边、中轴或基线。元素边界应落在外边距、栏边、沟槽中线或基线上；只有蓝图中声明的 1–2 个破格点可以例外。

字体外框不等于可见字面。尤其是宋体中文、窄英文和竖排组合，必须为每个标题轨记录 `box-left/right/top/bottom` 与 `ink-left/right/top/bottom` 两组边界。CSS/SVG 的 `x/y` 相同但可见字面相差明显时，以光学边界为准做确定性补偿，并把补偿写成变量；不要把每个字块散落成独立的 magic number。

推荐在 HTML 中把网格变量集中定义，不要为每个元素凭感觉写不同的 `left/top`：

```css
:root {
  --margin: 94px;
  --col: 208px;
  --gutter: 20px;
  --baseline: 32px;
  --c1: 94px;
  --c2: 322px;
  --c3: 550px;
  --c4: 778px;
  --c5: 1006px;
  --c6: 1234px;
}
```

截图前逐项检查：

- 主标题、结构字、地点标签和资料栏的起点是否能回溯到上述变量；
- 各对齐组是否真正共享同一坐标，而不是肉眼近似；
- 小字是否站在同一基线节奏上；
- 建筑占位是否跨明确栏位，并为文字留下有意的负空间；解释注释模式才预留专用引线通道；
- 关闭网格后，秩序仍由对齐和间距显现，而不是靠可见栏线撑住。

主题文字模式再检查：画面关闭网格后不出现短横线、边框、下划线、箭头、端点或用线模拟的装饰；所有分组都由字级、字重、色彩、留白、反白和遮挡完成。

### 标题组而不是标题碎片

建筑名拆成地点词、对象词和拼音时，先创建一个父级锁定组件，再在内部排轨。不要把三段文字分别绝对定位到大致相邻的位置。

三轨竖向标题推荐结构：

```text
左轨：真实拼音或英文地名，微字，竖向或旋转 90°
中轨：对象名，例如“古戏台”，Black/Heavy，第一层级
右轨：地点限定词，例如“沙溪”，Regular/Medium，第二层级
```

- 三轨的 x 坐标由同一个父级起点、轨宽和固定沟槽推导；
- 中轨必须在缩略图中最先被看见，笔画量明显高于两侧轨；
- 至少共享顶边与底边中的一项，并再共享一条基线或可见字面边；
- 拼音不得单独落在标题下方形成第四个游离方向；
- `grid-check` 同时显示父级框、三条轨道和可见字面框；`layout-guide` 隐藏这些检查线。

## 文字禁穿区与线条路由（仅解释注释模式）

对每个可读文字框建立 `exclusion zone`。资料字向外扩张至少 `0.5em`，展示字向外扩张至少 `0.25` 个字高。功能线与引线只能在禁穿区之外运行。

- 顶部规则线放在标题块之前或之后的独立基线上，不能穿过第二行大字。
- 分割线的任务是分组；若没有两个信息组需要分隔，就删除。
- 注释引线从标签框边缘进入专用沟槽，再转向构件；一个终点只对应一个标签。
- 引线需要跨越建筑时，放在建筑上方并使用高对比实线；需要被建筑截断时，明确把它放到建筑后方。不要让线条在同一段路由中忽前忽后。

## 重叠契约

垫图中的每次重叠必须预先写清：

```text
参与元素：结构字 TAIPING TOWER + 建筑屋檐
共同关系：二者共享第 5 栏边界；屋檐沿照片主对角线切入
z 顺序：结构字在后，建筑在前
重叠范围：结构字右侧 18%–25%
视觉任务：把天空文字层与建筑层连成一个空间
保护区：主屋脊、匾额、屋脊兽不被文字覆盖
```

文字彼此重叠比文字—建筑重叠更严格：必须共享基线或边线，并通过反白、透明、裁切或明确 z 顺序保持至少一个词完整可读。两个大字只是相互压住，或一个词随机碰到另一个词，不算设计。

## 避免把海报排成网页

前端只是精确排版工具，不意味着使用产品界面语法。下列 CSS/组件模式在海报垫图中默认禁用：

- 为每条注释复用相同的 `background + padding + box-shadow`；
- 用边框按钮或彩色胶囊分别包住年份、地点和状态；
- 把信息平均分成三张等权卡片；
- 用组件间距代替标题尺度、字重和留白层级；
- 把编号、图标、标签做成仪表盘或后台管理界面。

正确做法是把 HTML 当成精密排版台：

- 所有注释默认透明背景；
- 用共享基线、栏边、字级比例和字距建立秩序；
- 用一次反白、一次裁切或一次建筑遮字制造空间变化，而不是给每块内容加容器；
- 先问“这段字属于标题、结构字、资料列还是构件注释”，再决定字号和位置；不要先创建组件再填内容。

同时做一次“孤立元素检查”：任何角落标签、色块、图章、圆形或编号若不能同时连接主题内容和至少一个对齐/遮挡关系，就删除。版面的丰富度来自层级、尺度和材质冲突，不来自组件数量。

## 交给图像模型

明确输入角色：

```text
Image 1: edit target and sole source of architectural geometry.
Image 2: frontend-rendered layout-only reference; contains no target-photo pixels and defines only text bounding boxes, shared alignments, line breaks, neutral subject footprint, negative space, and occlusion direction. In explanatory-annotation mode only, it may also define functional-line endpoints.
```

提示模型“整体重绘”而不是“粘贴数字文字”，并明确：

- Image 2 的空间关系优先于纯文字描述；
- Image 2 的中性建筑占位不是材质参考，必须用 Image 1 的真实结构替换；
- 继承大致字体类别、字号比例、边界框和共同轴线；
- 文字、建筑、纸张和网点要共享同一印刷语言；
- 允许自然字形变化，但不得增加文案；
- 原照片仍是建筑几何、匾额、装饰和视角的唯一来源。

## 单独约束建筑与背景

排版垫图只解决“放在哪里”，不能解决“处理成什么”。提示词还要明确：

- 抠取整座、屋顶线、局部构件或连续街巷；
- 压缩成 2–4 个明度阶中的哪几阶；
- 屋顶、墙体、斗拱、树木、水面等区域分别使用网点、平涂、线刻、实景或剪影；
- 是否增加套色偏移、阴影回声、描边或局部保留原色；
- 原天空是保留、压低还是完全替换；新背景使用什么色场、纹理频率和明度；
- 明确禁止 `unchanged photo pasted onto a new background`、`raw photographic cutout` 和 `one uniform grain layer`。

如果只写“做成复古海报”，模型很容易选择最保守的原图抠图；必须把区域性材质变化写成可检查的动作。

不要把可见的栏线图作为生成输入，否则模型容易把网格线当成海报装饰。

## 验收与迭代

将输出和 `layout-guide` 并排检查：

- 主要共享边线的偏差最好不超过画布宽度约 1%–2%；
- 正立面建筑主轴与画布垂直轴的偏差最好不超过约 `0.5°`；若保留斜透视，必须在蓝图说明这是叙事选择而不是遗漏校正；
- 文字块的宽高、换行和方向没有发生结构性改变；
- 标题拆分项仍保持为一个锁定组：主标题字重和字面面积占优，地点词与拼音没有漂成独立装饰；
- 建筑仍占据相同主要区域，负空间没有被随机填满；
- 强风格化任务中，建筑内部和天空已经按材质方案发生可见变化，而不是原图加颗粒；
- 遮挡方向保持一致，身份保护区没有被文字覆盖；
- 主题文字模式没有任何可见规则线或引线；解释注释模式中的功能线均未进入文字禁穿区；
- 每处重叠都能回溯到一条重叠契约，而不是生成时随机发生；
- 每条构件注释都指向照片里的唯一目标，并且标签内容有来源；
- 注释主要以裸排文字、资料列或反白小字出现，没有重复卡片、按钮、胶囊和投影；
- 文案基本正确且没有额外乱码、微型资料、标志或水印。
- 建筑、天空、环境与前景均发生了区域性材质变化；不能是“原建筑抠图 + 新文字”或“原图统一加颗粒”。
- 没有孤立在角落、不能解释其主题来源与空间任务的装饰。

若某一处失败，修改垫图中对应的字号、边界框、裁切多边形或对齐线，再整体重绘。不要用越来越长的提示词补偿一个错误的视觉边界框，也不要默认在结果上重新堆叠文字。
