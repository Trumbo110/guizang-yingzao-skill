# 要素选择、处理推断与逻辑混搭

本流程把参考图转换成设计变量，再依据目标照片选择兼容组合。目标不是复刻某张参考图，也不是把多个参考的显眼元素平均叠加。

## 阶段 A：建立候选集

1. 先读 [token-system.md](token-system.md)，用 [design-element-library.md](design-element-library.md) 解释判断，并从 [design-tokens.json](design-tokens.json) 选择稳定 Token ID。
2. 新增扩展参考逐张读取 [reference-encoding-expansion-2026.md](reference-encoding-expansion-2026.md)；不得只读末尾归纳而跳过对应图片卡。
3. 每项观察分成六栏：`事实观察`、`视觉作用`、`可借用模块`、`目标照片对应物`、`禁用条件`、`跨文化删除项`。
4. 将相同作用的要素归为候选集，例如“建立背景尺度”的候选可以是来源正文场、低对比大字、单个色窗或建筑阴影；它们不是必须全部使用。
5. 删除无法解释作用、依赖原图品牌、没有目标照片几何对应物或文化语境不匹配的元素。

纯文字参考只向字体、网格、密度和留白候选集供给变量；不得因此生成虚构内容。外国建筑和外文参考先记录原机制，再通过“中式转译编译器”，不能直接成为风格模板。

可以先运行：

```bash
python3 scripts/design_tokens.py query --tag <照片关键词>
python3 scripts/design_tokens.py query --compatible-with <主导 Token ID>
python3 scripts/design_tokens.py recipe <Recipe ID>
```

检索结果只是候选。`visual` 字段只用于目录色片；真正选择仍依据照片几何、事实来源和 `requires / conflicts / constraints`。

## 阶段 B：读取目标照片

### 几何诊断

- 主导轴：垂直、水平、中轴、对角线、消失点或无明显轴。
- 主体占比与位置：完整、偏侧、局部、远景、被遮挡。
- 身份锚点：哪些构件一旦丢失就无法认出。
- 可用负空间：天空、墙、水面、地面、阴影、门洞。
- 原生节奏：重复檐口、柱网、砖缝、街巷、层数。

### 影像诊断

- 主体与背景的明度/色相差。
- 光影方向、过曝、欠曝、雾霾、杂乱物体。
- 哪些区域适合实景、网点、线稿、剪影或平滑保留。
- 输出尺寸下能保留到哪一级细节。

### 语境诊断

- 历史建筑、修复重建、仿古或当代项目。
- 可验证的名称、地点、年代、类型和设计者。
- 是否允许出现人物、地图、旧照、品牌或旅行记录信息。

### 排版诊断

- 哪一块负空间适合结构性大字，哪一块暗部适合反白短词。
- 主标题、结构字、地点组和主题词分别共享哪些左边、右边、中轴或基线。
- 建筑轮廓在哪些连接区可以遮字，哪些身份保护区绝不能被覆盖。
- 信息模式默认为主题文字；只有用户明确要科普或导览时才规划构件标签与引线。
- 若候选包含字窗、连续多窗、纹样遮罩或路径随形文字，先确认目标照片中确有可对应的短词、主体轴、来源纹样或真实曲线；任何一项缺失都删除该候选。

## 阶段 C：推断处理手法

| 目标照片特征 | 优先抠图范围 | 合适材质 | 常用版式 | 避免 |
| --- | --- | --- | --- | --- |
| 高塔、楼阁、正立面 | 完整轮廓或窄长塔身 | 线刻、细网点、高反差黑白 | 中心纪念碑、竖排字、背景大字 | 粗阈值吞掉檐口层数 |
| 对称院落、中轴水面 | 屋面+墙体+中轴，保留水面 | 双色实景+局部线稿，水面平滑 | 中轴网格+偏置色块 | 完全居中且所有信息对称 |
| 低机位重复屋檐 | 局部屋檐和天空边界 | 彩色套印、粗网点、描边 | 强对角线+负空间大字 | 强行展示完整建筑 |
| 街巷透视 | 连续屋檐、道路与消失点 | 灰度照片、局部橙色、窄栏 | 透视线+竖题+资料列 | 全图边缘检测造成噪声 |
| 单个构件特写 | 构件本身或局部剪影 | 粗网点、Xerox、木刻 | 全幅细节+细线注释 | 加入过多历史正文 |
| 背景杂乱、主体清楚 | 核心轮廓或主立面 | 剪影、双色、白色描边 | 纸面+色块托底 | 保留所有树叶、游客、电线 |
| 原生色很强 | 保留代表色构件 | 限色彩照、局部原色 | 互补背景+同色标题 | 再加入无关强调色 |
| 多栋建筑/系列照片 | 2–4 个有主次的图片块 | 统一灰度或统一双色 | 8/12 栏拼贴 | 每张图使用不同滤镜 |
| 塔/门楼有强中轴和突出塔刹 | 完整塔身+身份锚点 | 细网点、线刻、双色套印 | 字窗、连续竖窗、同轴多窗 | 把全部主体锁在字形内 |
| 建筑依山、城墙沿地形 | 建筑+必要坡面 | 方向性网点、地形频率带 | 地形—建筑融合 | 凭空生成等高线、山水线 |
| 真实窗棂/砖雕/彩画清楚 | 主体+一个纹样采样区 | 低对比照片、限区重复纹样 | 纹样边缘遮罩 | 泛龙凤祥云、整幅铺纹样 |
| 同一地点有可信旧照/图纸 | 对齐轮廓或 2–3 个同址图块 | 实景+可信档案层 | 半实景分割、同轴多窗 | 模型虚构结构与历史影像 |

## 阶段 D：组合语法

每张海报选择：

- 一个基础构图原型；
- 一个主要建筑提取范围；
- 一个主材质和最多一个辅助材质；
- 一套字体角色系统；
- 一个配色来源和一个强调色逻辑；
- 一个主要空间冲突；
- 零或一个语境插入层。

先完成字体角色、网格占位和遮挡契约，再决定辅助图形。圆形、印章、线条、坐标、页码、人物或地图都不是必选项；若不能同时连接主题来源与构图关系，就不进入组合。

推荐视觉权重约为 `60% 主导机制 / 30% 辅助机制 / 10% 点睛机制`。这不是颜色比例，而是设计注意力比例。

### 兼容组合

| 基础构图 | 常见兼容项 | 谨慎或不兼容项 |
| --- | --- | --- |
| 中心纪念碑 | 背景大字、建筑剪影、线刻、底部资料栏、单个偏置色块 | 强对角线主体、密集多图拼贴、多个表现型字体 |
| 中轴院落 | 分材质、中央栏缝、偏侧竖题、平滑水面、结构性大字 | 完全对称排字、横向多图、遮住入口和中轴 |
| 侧边切入 | 大留白、圆形托底、竖排地点、边框 | 密集正文、第二个大型建筑主体 |
| 对角线楔形 | 天空负空间大字、建筑取色、互补背景、屋脊插入物 | 中心标题、完整矩形照片、水平底栏过重 |
| 半实景分割 | 纸面、工程线稿、对齐轮廓、低信息量标题 | 粗网点再叠复杂拼贴、多个几何符号 |
| 多图拼贴 | 8/12 栏、统一强调色、窄栏正文、标题越栏 | 巨大红圆、中心纪念碑、书写体大面积跨图 |
| 局部巨像 | 粗网点、低对比大字、少量资料、全幅色场 | 长历史正文、多个地点标签 |
| 字窗纪念碑 | 短中文名、单体中轴、身份锚点越界、限色建筑 | 长标题、多图拼贴、重复地名、第二个完整主体 |
| 连续竖窗/同轴多窗 | 塔/门楼、统一底图、单个色带、局部放大 | 互不相关照片、圆角卡片、随机色条、不同滤镜 |
| 来源正文场 | 低对比纸面、建筑遮挡、清楚前景标题 | 另一组密集背景字、长英文、图标群、假印章 |
| 地形—建筑融合 | 山寺/城墙、双色、不同线频或网点频率 | 院落正立面、全图描边、可见路线线、纹样满铺 |
| 纹样边缘遮罩 | 单体建筑、来源纹样、1–2 个遮罩区、低信息标题 | 字窗主导、密集拼贴、泛传统符号、覆盖身份锚点 |

### 模块数量与互斥

- 字窗、连续竖窗、同轴多窗和模块拼贴都属于“主体容器机制”，一张海报只选一个。
- 来源正文场、重复短地名和尺度数字都属于“背景尺度机制”，默认只选一个；选择尺度数字后，数字必须是事实主语义。
- 地形频率场、区域纹样遮罩和可信档案层都属于“语境材料层”，最多选一个。
- 书写标题、随形文字和巨型几何字都属于“表现型文字动作”，最多选一个；资料字体保持中性。
- 单个色窗可以辅助中心纪念碑、侧边切入或字窗，但必须同时连接标题色和建筑轮廓；否则删除。
- 可见边框、路线、圆规线、显性模块格和注释引线统一受 `Line policy` 控制。主题文字模式或用户禁线时全部关闭。

这些限制以 `design-tokens.json` 的 `mutex_groups` 为机器可读真源。自然语言与 Token 发生差异时先修正两者，不要静默选择一个版本。

### 冲突预算

- 只选一个主要冲突，例如“严整中轴 vs 右侧偏置红块”或“精密线稿 vs 粗网点”。
- 次要冲突最多一个，例如“大宋体 vs 小无衬线”。
- 其他元素负责重复和稳定，不继续制造新冲突。

### 语境插入层

人物、地图、旧照、器物和图纸必须满足至少一项：来自用户素材、来自可核实公开资料、或由建筑本身直接推导。插入层需要明确标注是图示还是现场，不得伪装为原照片内容。

### 中式转译编译器

对每个外国建筑、纯外文或异国纹样参考模块依次编译：

```text
原参考视觉机制：<只写几何、字体角色、材质和 z 关系>
目标照片几何对应：<塔身/门洞/檐口/柱网/坡面/负空间>
中文语义接管：<中文主标题；可选真实拼音/译名>
地域材料接管：<建筑原生色、构件纹样、题记、可信图纸或地域材料>
保留：<机制中仍有效的部分>
删除：<外国地名、建筑、符号、人物、徽章、广告、二维码和装饰物>
失败信号：<换掉地名仍像原国家/品牌；没有目标建筑独有要素；只补红圆/书法>
```

每张方案最多采用两个经转译的外来机制，只允许一个作为主导。最终方案至少有两个来自目标建筑本身的独有锚点，并且中文在缩略图中先于任何外文被识别。

## 阶段 E：候选方案与选择

在重要任务中先提出最多三个方案，每个方案只写机制：

```text
方案名：
Recipe（可选）：
已选 Token ID：
依赖展开后 Token ID：
基础构图来源机制：
目标照片几何对应：
建筑提取与材质：
字体系统：
配色来源：
主要遮挡：
跨文化保留/删除：
为何匹配目标照片：
风险：
```

按以下维度各评 1–5 分：建筑身份、照片适配、元素兼容、空间层次、文字准确、缩略图识别。优先选择总分高且没有单项低于 3 的方案，而不是元素最多的方案。

方案确定后运行 `design_tokens.py recipe` 或人工展开 `requires`。任一互斥槽超额、任一 `conflicts` 命中或硬依赖缺失，方案直接无效；不能用降低透明度等视觉补丁绕开结构冲突。

## 阶段 F：编译成生成提示词

提示词顺序：

1. 输入图片角色与不可复制内容。
2. 目标照片身份锚点与不可改变项。
3. 画布、基础构图、网格占位和主体边界。
4. 从后到前的层级栈。
5. 字体角色和逐字文案。
6. 抠图范围、主/辅助材质和区域差异。
7. 颜色来源、面积和强调色连接对象。
8. 遮挡图和身份保护区。
9. 跨文化删除项与中式语义接管。
10. 选中 Token 的约束和 ID；只编译其 `prompt`，不把 Recipe 名当风格词。
11. 失败条件。

不要把要素库全部写进提示词。只编译已经选中且彼此兼容的组合。

编译后做一次删减：移除所有孤立小字、角落装饰、无意义英文、默认红圆/印章和无法解释的线。排版仍应依靠共享轴线、尺度差、色彩和遮挡成立。

再做一次“模板残留检查”：隐藏中文地名后，若画面仍主要依靠异国字形、宗教符号、外国建筑轮廓、旅游徽章或原参考配色才成立，说明没有完成转译。保留几何关系，替换文化名词、材料和图形来源后重新编译。
