# 太平楼真实字体混合排版测试

## 结论假设

真实字体和 CSS 网格先行可以先稳定字形比例、字距、对齐线、跨栏与基线；把排版垫图作为图像模型的构图参考，可以提高负空间、主体占位、文字尺度和色场关系的服从度。最终仍由图像模型整体重绘，因此允许少量字形和像素级对齐漂移，换取文字、建筑与印刷材质更自然的一体化。测试不做生成后的文字回叠。

## 目标照片诊断

- 对象：大同古城太平楼；只使用用户确认的名称与地点，不添加年代和历史断言。
- 主导轴：多层屋檐从左下指向右上，强对角线；不是中轴建筑。
- 主体占位：建筑集中于右侧和下部，左上天空是天然文字负空间。
- 身份锚点：三层屋檐节奏、顶层山花、彩绘斗拱、匾额、红色立面。
- 原生配色：朱红、深青灰、金色和浅蓝天空；主强调色直接取自建筑朱红。
- 处理策略：保留完整对角线建筑群，不抠成孤立楼体；天空低频纸化，暗部细网点化，屋脊与檐口允许少量米白线稿。

## 六栏网格

- 画布：1536 × 2048，3:4。
- 外边距：88px，约 5.7%。
- 栏宽：210px；沟槽：20px。
- 栏起点：88 / 318 / 548 / 778 / 1008 / 1238。
- 基线：32px。
- `TAIPING / LOU` 从第一栏起，跨前五栏，但被近似天空轮廓裁切，模拟位于建筑后方。
- `太平楼` 从第一栏起竖排，占一栏并轻微越入沟槽。
- `大同古城` 锚定第二栏起点附近，与主标题形成一宽一窄的竖向节奏。
- 顶部资料、主规则线和结构性大字共享第一栏左边线；规则线终点落在第四栏边界附近。

## 字体角色

| 文案 | 字体 | 角色 | 位置与层级 |
| --- | --- | --- | --- |
| `太平楼` | Songti SC，900 | 主展示标题 | 朱红、竖排、前景 |
| `TAIPING / LOU` | Alibaba PuHuiTi ExtraBold | 低对比结构字 | 深青灰 18%，裁切在天空区域 |
| `大同古城` | Alibaba PuHuiTi ExtraBold | 地点标签 | 深青灰、小型竖排 |
| 顶部资料 | Alibaba PuHuiTi ExtraBold | 方向与编号 | 第一栏左对齐，连接水平规则线 |

字体二进制不由图像模型生成。测试机器优先使用本地 Songti SC 和 Alibaba PuHuiTi；换环境时应替换成明确授权的本地字体或通过 `@font-face` 引用已下载的 Google Fonts 字体文件。

## 层级与遮挡

1. 浅蓝纸化天空。
2. 被天空多边形裁切的低对比 `TAIPING / LOU`。
3. 原照片几何不变的朱红建筑材质底图。
4. 朱红 `太平楼`、地点标签和功能规则线。

结构性拉丁字通过 CSS `clip-path` 留在天空范围内，使其看似被建筑遮住；中文主标题位于前景，仅在低信息檐口附近轻微叠压。匾额、屋脊兽、山花和主要斗拱属于不可遮挡区。

## 生成流程

1. 用 [taipinglou-hybrid-layout.html](taipinglou-hybrid-layout.html) 和原照片渲染排版控制图，可打开网格检查。
2. 将原照片标为 edit target，将不显示栏线的排版图标为 composition/layout reference。
3. 要求图像模型整体重绘建筑、文字和材质，同时尽量继承垫图中的文字内容、字体类别、边界框、栏位、基线和遮挡关系。
4. 可见网格图只用于人工检查，不进入最终生成输入；功能规则线可以保留，栏线不能作为装饰出现。

如果输出只有局部对齐偏差，下一轮只修正垫图中的对应边界框或对齐线，再整体重绘；不在生成结果上重新堆叠文字。

## v1 测试结果

- 输出尺寸：1086 × 1448，保持 3:4。
- `太平楼`、`大同古城`、`TAIPING`、`LOU` 和顶部信息均正确生成，没有额外文案。
- 顶部信息、结构性大字、主标题和地点标签保留了垫图中的共同左边线与上下节奏；`TAIPING` 与 `LOU` 的宽度出现轻微重绘差异，但没有重新漂成独立模块。
- 水平规则线的起点、终点和红点关系被保留；可见网格没有进入成品。
- 建筑原生朱红、浅蓝纸面、深色斗拱和细颗粒统一成同一印刷语言，优于把锐利数字文字后贴在生成图上的割裂感。
- 残余风险：建筑匾额也属于图像中的文字，整体重绘可能改变局部笔画。正式发布前仍应对照原图检查匾额，必要时把匾额列为更强的身份保护区重新生成。

这次测试支持“排版垫图能显著改善整体网格，但不追求像素级复刻”的判断。
